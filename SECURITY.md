# Security Policy

## Supported Versions

Security fixes are provided only for the latest published release of the latest major version.

Current policy in practice:

- While major version is 1, only the newest 1.x release is supported
- If major version 2 is released, only the newest 2.x release is supported by default
- Older major versions are not guaranteed to receive security fixes

| Version | Supported |
| ------- | --------- |
| latest (current major) | :white_check_mark: |
| older releases         | :x:                |

## Reporting a Vulnerability

Please do not open a public issue for suspected vulnerabilities.

Use one of the following channels:

1. GitHub Security Advisories (preferred)
2. If advisories are unavailable, open an issue with minimal details and request a private contact channel before sharing technical details

When reporting, include:

- affected package version
- impact and attack scenario
- proof of concept or reproduction steps
- suggested fix (if available)

## Response Expectations

- Initial triage response: within 7 days
- Status updates: every 14 days until resolution

## Disclosure Policy

After a fix is available, maintainers may publish a coordinated disclosure including:

- summary of impact
- affected versions
- remediation steps
- acknowledgment (if requested)
